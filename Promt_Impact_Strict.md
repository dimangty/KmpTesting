# ОБЯЗАТЕЛЬНАЯ СТРУКТУРА ДОКУМЕНТА

Твой ответ ДОЛЖЕН содержать РОВНО эти 4 раздела:

## 1. Impact analysis

Формат каждого изменения:
```
- [Краткое описание изменения] [ЦВЕТОВОЙ_КОД]: [детали]
```

Цветовые коды (ОБЯЗАТЕЛЬНО использовать):
- `#00F` - Low (текста, стили)
- `#0F0` - Mid (логика без больших изменений)
- `#F00` - High (новый модуль, экран, переписан большой блок)

Пример:
```markdown
- Добавлен новый экран "Kitchen Tips" #F00: экран для отображения кулинарных советов с недельным планированием
- Изменена навигация в ProfileScreen #0F0: добавлена кнопка перехода к Kitchen Tips
```

# ПРАВИЛА АНАЛИЗА DIFF

Анализируя diff, обращай внимание:

**Новые файлы** (new file mode) → #F00 или #0F0
**Удаленные файлы** (deleted file mode) → #F00 или #0F0
**Изменения в файлах**:
- `+` (добавлено) - новая логика/UI
- `-` (удалено) - старая логика удалена

**Паттерны для определения уровня**:
- Новый экран/Screen → #F00
- Новая навигация/Route → #0F0
- UI изменения (добавление кнопки, карточки) → #0F0
- Изменение текста/цвета → #00F
- Новый ViewModel → #F00
- Изменение в существующем ViewModel → #0F0
